## Method

License values below come from the `license` field recorded for each
package in the root `package-lock.json` (npm records this from each
package's own published `package.json` at resolution time). Where no
`license` field is recorded in the lockfile, this document says so
explicitly rather than guessing. Workspace-internal packages
(`@aoc-enterprise/*`, `packages/*`, `apps/*`) are excluded from this
table — they are Frontera Systems' own proprietary code, not third-party
dependencies (see `docs/legal/IP_OVERVIEW.md`). `@aoc/protocol` is
likewise excluded — it is a peer dependency on the separate Soberanía Protocol
project, not a conventional open-source dependency (see
`docs/legal/PROTOCOL_ENTERPRISE_BOUNDARY.md`).

The root lockfile is the single source of truth for the whole npm
workspaces monorepo (`workspaces: ["packages/*", "apps/*"]`) and
resolves 96 unique third-party/transitive package entries in total.

## Classification summary

- **Permissive:** MIT, Apache-2.0, ISC, BSD-2-Clause, BSD-3-Clause,
  0BSD, CC-BY-4.0 (data) — all direct and nearly all transitive
  dependencies fall here.
- **Weak copyleft:** none found.
- **Strong copyleft:** none found.
- **Unknown:** `busboy`, `streamsearch` (see above — license status
  requires manual verification).
- **Commercial:** none in the sense of a paid software license; `stripe`
  is a commercial *service* accessed through an MIT-licensed SDK (see
  above).
- **Proprietary:** none — all workspace-internal packages are
  Onchainfest LLC's own proprietary code and are intentionally excluded
  from this third-party inventory (see `docs/legal/IP_OVERVIEW.md`).
- **Dual licensed:** `expand-template`, `rc` (see above).

## Known repository hygiene gaps (not license risks, but affect
reproducibility of this inventory)

- `apps/agent-passport-web` has its own standalone `package-lock.json`
  in addition to being resolved through the root workspace lockfile —
  this could drift from the root-resolved versions over time and should
  be reconciled or removed by engineering.
- Several packages' test scripts reference `tsx` (e.g. via
  `node --import tsx --test`), but `tsx` is not declared as a dependency
  anywhere in this repository — a build-reproducibility gap, not itself
  a licensing determination, worth engineering follow-up.
