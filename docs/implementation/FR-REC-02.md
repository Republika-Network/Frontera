# FR-REC-02 — Capital Discovery trusted context provider

`createCapitalDiscoveryContextProvider` implements Frontera's `ContextResolverPort`. It is a server-side fact bridge: the deployment declares `query.keys`, and an injected host reader answers exactly those keys from Capital Discovery marketplace state. Unsupported keys yield no observations. The provider accepts the FR-REC-01 action and resource vocabulary, preserves opaque refs, and safely returns no observations for unrelated, malformed, or incompatible scopes.

The reader supplies scalar values and observation times. Each accepted reading must have a real ISO-8601 calendar timestamp with seconds, optional fractional seconds, and `Z` or a numeric offset; invalid rows are omitted without replacing their timestamp. At most one accepted reading per requested key is allowed in a resolution call. Duplicate accepted readings fail with a bounded reader-contract error; Frontera's generic context adapter handles resolver failure as unresolved context. Invalid or unrequested rows do not count as duplicates.

The provider projects only permitted observation fields and adds its host-configured `sourceId`, which must be nonempty, exactly trimmed, free of ASCII/C1 controls, and at most 256 characters. Neither reader nor provider emits `trustClass` or governance decisions. Frontera's configured `ContextSourceRegistry` classifies the source; the source ID does not determine trust. The context service evaluates freshness. The requester cannot select the source or supply business facts. `organizationId` is an input identity, never membership or ownership proof. Signed-attestation observations are not supported in this slice.

This slice freezes no literal context-key vocabulary, public cross-repository package surface, or production host configuration. It does not implement FR-REC-03 policy predicates, matching, marketplace mutation, or direct database, HTTP, or storage access. Capital Discovery must recheck object ownership and transactional business invariants immediately before commit even after Frontera ALLOW.
